# 工作台接数据方案（第一版）

客户端组长，2026-11-17。总控派活：把商品后台调控、广告汇总、刊登进度三类数据接到 EDUPLINK 工作台上。

这一版先用假数据把页面做出来，接口到了再接上。字段口径以平台与经营组、广告组给的接口说明为准，下表的字段名都是**暂定的**，接口说明到了按它改。

## 1. 总的做法

- **取数**：页面一律走现有的 `api(route)`。桌面版走 `window.edup.request`，浏览器版走 `/api/<route>`，由网关转到各组的数据。客户端不直接读服务器、数据库和平台。
- **换数据源只改一个文件**：新建 `ui/board/board-data.js`，所有新页面都经它取数。
  - 现在它从 `ui/board/board-mock.js` 拿假数据；
  - 接口到了改成调 `api(route)`，页面代码不动。
- **假数据必须让人一眼看出是假的**：
  - 用假数据时，每页顶上一条醒目的横幅："演示数据，不是真实经营数据"；
  - 打正式包时默认关掉，只在开发和自检里打开。
- **没有数据就显示"—"**：写清楚原因（还没接通、报表还没出、只覆盖了部分 SKU），不当 0 处理。这和现在"广告分析"占位页的规矩一样。
- **每块数据都带三样东西**：
  - `asOf`：数据截至什么时候；
  - `source`：从哪来；
  - `coverage`：覆盖了多少，比如 SKU 数、站点。
  
  页面在标题下面写一行小字。广告报表有延迟，要单独写报表日期。
- **刊登各阶段分开说，批次数字不相加**（总控的汇报规矩）。看板上没有"合计"行。

## 2. 放哪些页

左边导航现在有 7 项：经营总览、商品管理、经营报表、上架、广告分析、运营 AI、同步与维护。改法如下：

| 页 | 改法 |
|---|---|
| 经营总览 | 在现有 KPI 下面加一排三张汇总卡：商品调控、广告、刊登。点卡片跳到对应页 |
| 商品管理 → 改名**商品调控** | 在现有商品表上加平台与经营组的字段：价格、库存、同步状态、利润 |
| 广告分析 | 把现在的占位页换成真页面 |
| **刊登进度**（新加，放在"上架"后面） | 按批次看各阶段数量和失败原因。"上架"页本身不动 |

## 3. 每页的字段和来源

### 3.1 经营总览：新加三张卡

| 卡 | 显示什么 | 来源 |
|---|---|---|
| 商品调控 | 在售 N、缺货 N、价格待处理 N、同步异常 N（待回读、超 24 小时没回读） | `board/products` 的 `summary` |
| 广告 | 近 7 天花费、广告销售额、ACOS，再加报表日期 | `board/ads` 的 `summary` |
| 刊登 | 进行中的批次数；最近一批各阶段的数量 | `board/listing-progress` 的第一批 |

### 3.2 商品调控（平台与经营组出数据）

暂定接口 `board/products`，参数 `{site}`。返回 `{asOf, source, coverage, summary, items[]}`。

每个商品（`items[]` 一行）：

| 字段（暂定） | 页面上叫 | 说明 |
|---|---|---|
| `site`、`sku`、`asin`、`name` | 站点、SKU、ASIN、商品名 | 现有快照里就有 |
| `status` | 在售状态 | 在售、停售、暂停同步（paused-skus）、没上架 |
| `available`、`reserved` | 平台可售数、预留 | 现有快照里就有 |
| `supplierStock` | 供应商库存 | GigaCloud 读到的数 |
| `price`、`currency` | 当前售价 | |
| `priceFloor`、`priceCeiling` | 价格护栏 | 对应 price_guard |
| `priceAction` | 价格待处理 | 比如"低于护栏，已拦下"、"待人工确认" |
| `unitProfit`、`margin`、`fxRate`、`fxDate` | 单件利润、利润率、汇率和汇率日期 | 来自利润汇率作业；没算出来显示"—" |
| `syncState` | 同步状态 | 正常、待回读、超 24 小时没回读、出错。对应 awaiting_offer_readback / offer_readback_overdue |
| `lastSyncAt` | 上次同步 | |
| `issues[]` | 问题 | 现有快照里就有 |

页面怎么做：
- 筛选：站点、在售状态、同步状态、"只看有问题"、搜 SKU。
- 点一行打开右侧详情，显示最近几次价格和库存变化。数据从 `board/products/history {sku}` 来，对应 ledger_view。
- **只看不改**：这一版没有改价格、改库存的按钮。要加，等用户另外拍板。

### 3.3 广告分析（广告组出数据）

暂定接口 `board/ads`，参数 `{site, from, to}`。返回 `{reportDate, source, importedFiles[], summary, compare, campaigns[], skus[], wastedTerms[]}`。

现在广告 API 还没给，数据是人从广告后台导出、广告组离线算出来的。页面要写清：
- 用的是哪几个导入文件、什么时候导入的；
- 报表覆盖到哪一天。

| 区块 | 字段（暂定） | 说明 |
|---|---|---|
| 汇总 KPI | `spend`、`sales`、`orders`、`impressions`、`clicks`、`ctr`、`cpc`、`cvr`、`acos`、`roas` | 对应广告组 A2 的指标。分母为 0 时显示"—" |
| 和上一段时间比 | `compare` 里同一套指标，加变化 | 对应 A2 的对照期 |
| 盈亏线 | `breakEvenAcos`、`targetAcos` | 对应 A3 |
| 按广告活动 | `campaigns[]`：名称、花费、销售、订单、ACOS、ROAS | |
| 按 SKU | `skus[]`：SKU、花费、广告销售、ACOS、盈亏平衡 ACOS；高出盈亏线的标红 | |
| 只花钱没出单的词 | `wastedTerms[]`：搜索词、花费、点击 | 对应 A2 的零出单花费，取前 20 个 |

页面怎么做：
- 时间范围（近 7 天、近 30 天、自定义）加站点筛选。
- 这一版**只看不改**，没有调出价、停词的按钮。

### 3.4 刊登进度（要定由哪组出接口）

暂定接口 `board/listing-progress`，参数 `{site}`。返回 `{asOf, batches[], backlog}`。

| 字段（暂定） | 页面上叫 |
|---|---|
| `batchId`、`createdAt`、`site`、`total` | 批次、开始时间、站点、本批款数 |
| `aiPassed` | AI 通过 |
| `preflightPassed` | 预检通过 |
| `submitted` | 已提交 |
| `accepted` | ACCEPTED |
| `hasAsin` | 有 ASIN |
| `buyable` | 可售 |
| `unknown`、`pending` | 待定（结果还没回） |
| `failed`、`reasonCodes{码: 数}` | 失败，以及按原因码分的数 |
| `state` | 进行中、已停（比如 STOP 文件在）、完成 |

页面怎么做：
- 一批一行，每一列就是一个阶段，**各列分开，不相加**。
- 点开一批，看原因码分布。原因码的中文说明用上架内核组的原因码手册。
- 积压单独放一块：`backlog.count`，现在是 925 款。写明"保持现状，不在这里处理"，不和批次放在一起算。
- **只看不改**：没有恢复批次、重发、清 unknown/pending 的按钮。这些都要用户逐次同意。

## 4. 代码放哪

- 新建文件夹 `client/ui/board/`，放这几个文件：
  - `board-data.js`：取数，假数据和真接口在这里切换；
  - `board-mock.js`：假数据；
  - `products-control.js`：商品调控页；
  - `ads-board.js`：广告分析页；
  - `listing-progress.js`：刊登进度页；
  - `board-cards.js`：总览上的三张卡；
  - `board.css`：样式。
- `app.js` 只改导航和分派，把页面交给 `ui/board/`。
- 新文件夹要在运维组的 `boundaries.json` 里登记成一个模块：`ui:board`，入口 `ui/board/index.js`，可以用 `ui:common`。客户端基线跟着重新生成。登记的要求写进运维组计划的"收到的需求"。
- 测试：
  - `test/board-*.test.cjs` 测取数层：切换假数据和真接口、没数据显示"—"、批次不相加；
  - 原生自检加一条 `run-native-board.cjs`：隐藏窗口里把三页都打开一遍，确认没报错、有横幅。

## 6. 做的顺序

1. 用假数据做 `ui/board/` 的取数层和三页，加测试和原生自检，门禁过了合 main。正式包里默认不用假数据，等于用户看不到新页。
2. 接口说明到了，改字段名和 `board-data.js`，换成真接口。
3. 网关路由上线以后，正式包里打开新页。上线跟着下一次整包走，要总控批准。
